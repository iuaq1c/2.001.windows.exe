# 2_1011_01-windows.exe — полный разбор

**Задача:** банковский сервис «Greenbank» (CTF, веб + статический анализ PE).
**Флаг:** `vsosh{n3tw0rk_1nt3r4ct10n}`

---

## 1. Кратко

Файл — 64-битное консольное Windows-приложение. Внутри не «банк с ассетами», а **локальный HTTP-сервис**: при запуске он поднимает веб-приложение на loopback-порту, отдаёт SPA и JSON API.

Уязвимость: маршруты с префиксом `/api/auth/` выглядят защищёнными, но **аутентификации на них нет**. Данные пользователя и его карты отдаются обычным `GET` без токена, cookie и заголовков.

## 4. Рантайм: Rust, а не C++

Строковый дамп (`51434` строки) содержит служебные сообщения, которые выдают конкретные библиотеки:

**Крейт `http`:**
`invalid header name`, `invalid header value`, `invalid new line`, `invalid HTTP version`, `too many headers`, `HeaderName`, `HeaderValue`, `NewLine`, `TooManyHeaders`

**Крейт `hyper`:**
`ContentLength`, `InvalidTransferEncoding`, `InvalidTransferEncodingUnexpectedBody`, `WriteAborted`, `UnexpectedHeader`, `Service`, `NoUpgrade`, `ManualUpgrade`

**Крейт `axum`:**
`Insertion failed due to conflict with previously registered route`
`Only one parameter is allowed per path segment`
`Parameters must be registered with a valid name`
`Catch-all parameters are on…`

**Крейт `serde` / `serde_json`:**
`expected struct AppStateEnvelope with 3 elements`, `serde_json::pr…`

DetectItEasy пишет MSVC, и это не противоречие: **Rust на Windows собирается MSVC-тулчейном**, поэтому линкер и CRT в заголовках — от Microsoft, а строки — от Rust-крейтов.

> Оговорка: точные версии крейтов по строкам не определяются. Вывод «Rust + axum + hyper + serde» — сильная реконструкция по сигнатурам сообщений, а не прямой вывод инструмента.

## 6. Динамический анализ

Запуск консольного exe → сервис слушает `127.0.0.1:53240`.

Корень `/` отдаёт HTML: `<title>Greenbank</title>`, `theme-color #0f7a4a`, подключает `/css/style.css` и `/js/app.js`, контейнер `<main id="app">`.

### Карта маршрутов и ответов

| Запрос | Код | Content-Type | Интерпретация |
|---|---|---|---|
| `GET /` | 200 | `text/html` | SPA |
| `POST /auth/login` | 200 | `text/html` | fallback |
| `POST /api/v1/auth/login` | 200 | `text/html` | fallback |
| `POST /ab2a7fb1-…/auth/login` | 200 | `text/html` | fallback |
| `POST /api/auth/login` `{"username":"useruser","password":"x"}` | **401** | `application/json` | отказ |
| `GET /api/state` | 200 | `text/html` | **fallback — маршрута нет** |
| `GET /api/auth/stats` | **200** | `application/json` | данные **без авторизации** |
| `GET /api/auth/cards` | **200** | `application/json` | карты **без авторизации** |

Ответ `/api/auth/stats`:

```json
{"username":"useruser","login_attempts":3,"successful_logins":0,
 "failed_logins":3,"password_changes":0,"last_login_at":null,
 "last_password_changed_at":null}
```

Ключевое правило разбора: **`text/html` в ответе на `/api/…` означает, что запрос ушёл мимо API** — это SPA fallback, а не «сервер ответил страницей». Отличать обязательно, иначе легко решить, что маршрут есть, но «странно отвечает».

## 7. Фронтенд

`app.js` (~21 KB). Регулярка по `/api/…` даёт шесть маршрутов:

`/api/state`, `/api/auth/stats`, `/api/auth/cards`, `/api/auth/login`, `/api/auth/change-password`, `/api/auth/change-password/request-code`

Обёртка над `fetch` (строки 63–66): в `headers` только `Content-Type` и `...(options.headers || {})`. **Ни `Authorization`, ни `X-Token`, ни `credentials`.**

Признак входа хранится в браузере:

```js
return sessionStorage.getItem(AUTH_KEY) === "1";
// ...
sessionStorage.setItem(AUTH_KEY, "1");
```

То есть «авторизация» в интерфейсе — косметический флаг в `sessionStorage`. Серверной сессии нет, клиент сам решает, показать экраны или нет.

## 8. Уязвимость

**CWE-306: Missing Authentication for Critical Function.**

Префикс `/api/auth/` создаёт иллюзию защищённого пространства, но проверки на этих маршрутах не реализовано. Подтверждение — обычный `GET` без единого заголовка вернул персональные данные и карты.

Дополнительно:

- `/api/auth/stats` — раскрытие имени пользователя и счётчиков (information disclosure);
- `/api/auth/cards` — раскрытие номеров и балансов;
- вход в интерфейсе подменяется установкой `sessionStorage` — обход UI в один клик.

### Открытый вопрос

`401` с пустым телом на `/api/auth/login` при заведомо неверных данных. Две равноправные версии:

1. отказ на слое аутентификации/middleware **до** обработчика;
2. отказ самого обработчика, вернувшего пустое тело.

По имеющимся данным различить нельзя — нужен трейс или поведенческий тест (например, изменился ли счётчик `login_attempts` при отказе).

## 9. Эксплуатация

```powershell
$b = 'http://127.0.0.1:53240'
Invoke-RestMethod "$b/api/auth/stats"   # профиль без авторизации
Invoke-RestMethod "$b/api/auth/cards"   # карты без авторизации
```

Ответ `cards` содержит массив карт; флаг лежит **в имени второй карты**: `n3tw0rk_1nt3r4ct10n`.

```text
vsosh{n3tw0rk_1nt3r4ct10n}
```

Название флага прямо описывает вектор: взаимодействие с сетью напрямую, минуя интерфейс.

Замечание по кодировке: `•••• 2481` в PowerShell 5.1 — артефакт декодирования UTF-8 как Latin-1 (`Invoke-WebRequest` отдаёт `RawContent` без учёта charset). На флаг не влияет, но парсить лучше через `Invoke-RestMethod`.

## 10. Как чинить

- серверная проверка сессии на **всех** `/api/auth/*`, кроме `login` и `request-code`;
- сессия — `HttpOnly` + `Secure` cookie либо подписанный Bearer-токен со сроком жизни;
- не хранить признак аутентификации в `sessionStorage` и не доверять решению клиента;
- лимит попыток входа и единые обезличенные сообщения об ошибке;
- алерт на `200` по защищённому маршруту без субъекта;
- bind на loopback — хорошо, но **не заменяет авторизацию**: локальные процессы и другие пользователи машины остаются в зоне риска.
